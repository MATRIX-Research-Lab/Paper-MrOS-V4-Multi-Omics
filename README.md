# MrOS multi-omics mortality analysis

Code and aggregate results for the MrOS all-cause mortality analysis.

Two analyses are reported. The **primary analysis** fits each omics layer in its
own analytic sample (765 / 447 / 446 men), each with its own train/test split.
The **matched-cohort refit** fits every layer on the same 332 men (169 deaths)
with shared folds and a single clinical benchmark, using nested
cross-validation, so the layers can be compared directly.

## Data availability

**No individual-level data are in this repository.** MrOS participant data are
controlled-access and the Data Use Agreement does not permit redistribution, so
`data/` is gitignored in full. Everything else is here: the analysis code, the
software environment, the provenance records, and the aggregate results under
`results/`.

Investigators with MrOS access can place the approved source files under
`data/raw_data/` and rebuild from scratch — see *Rebuilding from raw data*
below.

## Rendering the results

Every manuscript figure and table is generated by code here. Each entry point
owns its own outputs and only checks that the others are still present:

| Entry point | Produces |
|---|---|
| `Rscript code/single_omics/run_all.R` | primary and matched-cohort figures and tables, except the five figures below |
| `Rscript code/cross_omics/01_find_blocks.R` then `02_make_figures.R` | Fig 5, Supplementary Figs 3–4, and the cluster-name tables |
| `bash code/latex_workflow/run_all.sh` | Supplementary Figs 5–6 (workflow schematics) |

All three write into `results/`, which is the single source the manuscript is copied from.

`code/single_omics/run_all.R` runs `01_`–`05_` (primary) and `07_` (matched cohort).
It fits no models. It does not regenerate the cross-omics heat maps or the
LaTeX schematics; it only confirms those PDFs are still in `results/figures/`.

The cross-omics figures need `perm_workspace.RData` in `code/cross_omics/`
(not committed; see that folder's README). `01_find_blocks.R` writes the cluster
tables in about 20 seconds. `02_make_figures.R` draws Fig 5 and Supplementary
Figs 3–4 and must be run after `01`. The three `permute_*.R` scripts are
separate: each shuffles the Active / Deceased labels 500 times for one omics
pair and writes a p-value table. They do not read the output of `01` or `02`.

To copy the results into a manuscript folder and verify the copies are
byte-identical:

```bash
Rscript code/single_omics/sync_submission_assets.R "../manuscript/figures and tables"
```

Nothing is generated inside the manuscript folder; it only ever receives copies.

### Two sets of model outputs

`data/model_outputs/` holds three directories, and two of them are **not**
interchangeable:

| Directory | Used by | What it is |
|---|---|---|
| `single_omics/` | `01_`–`05_` | the primary analysis; every published primary figure and table is computed from these |
| `single_omics_rerun/` | `06_` only | a later re-fit of the same three layers, carrying the provenance manifests the matched stage records against |
| `matched_cohort/` | `07_` | output of the matched-cohort refit |

The two layer-specific sets agree on the analytic samples — same participants,
same feature blocks — so the matched cohort is the same either way. They differ
in two respects that the code handles explicitly: the re-fitted objects carry
provenance manifests, and they store risk as the predicted death probability
where the primary objects store its complement. See the comments on `paths` in
`code/single_omics/00_setup.R` and on `validate_prediction_output()` in
`code/single_omics/analysis_provenance.R`.

## The heavy stages — not part of a routine run

These are deliberately outside `run_all.R`, and none of them is needed to
regenerate the results:

| Script | Does | Note |
|---|---|---|
| `code/single_omics/preprocess_data.R` | rebuilds `data/processed_data/` from raw MrOS files | **do not run casually** — see below |
| `code/single_omics/run_omics_pred.R` | refits the primary layers | writes `single_omics/` |
| `code/single_omics/06_fit_matched_cohort_models.R` | refits the matched cohort | over an hour; reads `single_omics_rerun/` |

`code/single_omics/preflight.R --stage matched|render|primary` is a read-only check to run
before any of them. `code/single_omics/smoke_omics_pred.R` exercises the fitting pipeline on
a subsample.

### Rebuilding from raw data

```bash
Rscript code/single_omics/preprocess_data.R --overwrite
```

It refuses to write a result unless these contracts hold:

| Layer | Participants | Deaths | Omics features |
|---|---:|---:|---:|
| microbiome | 765 | 439 | 147 |
| metabolomics | 447 | 216 | 1,574 |
| proteomics | 446 | 215 | 7,596 |

The three-way overlap must be 332 men with 169 deaths.

**The three modeling frames are frozen inputs.** Regenerating them under a
different package stack moves every downstream result. Their MD5 checksums:


## Cross-omics figures and cluster tables

`Fig5_micro-metab_correlation.pdf.pdf`, `Supplementary_Fig3_micro_prot.pdf` and
`Supplementary_Fig4_meta_prot.pdf` are produced by
`code/cross_omics/02_make_figures.R`. `code/single_omics/run_all.R` never
regenerates them; it only confirms they are still present in `results/figures/`.

```bash
Rscript code/cross_omics/01_find_blocks.R
Rscript code/cross_omics/02_make_figures.R
```

`01_find_blocks.R` also writes the cluster membership CSVs to `results/tables/`
(`cross_omics_*_microbiome.csv`, `cross_omics_*_metabolites.csv`,
`cross_omics_*_proteomics.csv`, and `cross_omics_block_summary.csv`).

The permutation p-values are a separate run, about three hours for all three
pairs on one machine:

```bash
Rscript code/cross_omics/permute_micro_metab.R
Rscript code/cross_omics/permute_micro_prot.R
Rscript code/cross_omics/permute_metab_prot.R
```

Each script writes `results/tables/cross_omics_perm_<pair>_node<NN>.csv`.
`perm_id = 0` is the observed split. The p-value comes from the 500 shuffles.
Details and the local `perm_workspace.RData` step are in
`code/cross_omics/README.md`.

## Reproducibility notes

- **PDFs are not byte-reproducible.** `cairo_pdf` embeds a creation timestamp,
  so two renders of identical data differ in bytes. Compare the CSV files
  written alongside each table, which are byte-stable, or compare the PDF
  drawing content rather than the file.
- A fresh environment will not reproduce the published numbers to the last
  digit: `glmnet`, `ranger` and `xgboost` change their RNG between versions.
  `environment/` pins the stack that produced the cluster results.
- `AUC_CI_table.xlsx` stores AUCs at full double precision, so two of its 114
  cells can differ in the 15th significant digit depending on the order pROC
  sums in. Nothing changes at any reported precision — every table and figure
  rounds to three decimals. Compare that file at three decimals, not by md5.
- The delta-AUC tables pair a **bootstrap percentile** interval with a **DeLong**
  P value. Both are valid, but they are different procedures and are not
  constrained to agree on a marginal comparison; one published row differs in
  verdict. Captions should say which is which. See `build_delta_auc_table()`.

## Open questions for the collaborator

Carried over from reconciling the original analysis with the later re-run.
These are known, not hidden:

1. **`manuscript/figures and tables/` currently matches the re-run, not this
   repository.** `results/` here is the primary analysis; the manuscript's
   copies came from the re-run, and the two disagree — e.g. proteomics EN pooled
   out-of-fold AUC 0.729 here vs 0.697 there. Matched-cohort numbers are
   unaffected. Re-syncing means the primary numbers in the text move.
2. **Figure 2's ROC curves were re-oriented (fixed 2026-08-11).** The saved
   curves in `single_omics/` were built with survival as the event — the
   modelling frames carry `status` as levels `c("Deceased", "Active")` and the
   first level was taken as the event — so all 15 (3 layers × 5 models) were the
   ROC of predicting *Active*: same AUC, mirrored shape, sensitivity off by up
   to 0.27 at a fixed specificity. `roc_bind_five()` now recomputes every curve
   from the stored test-set predictions through `roc_death()`, which pins
   cases = Deceased. **No AUC, CI, ΔAUC or table changed** — AUC is invariant
   to the swap — and no model was refitted. `Fig2_roc.pdf` is the only artifact
   affected. The re-run outputs never had this bug, so the manuscript's copy of
   Figure 2 was already correctly oriented.
3. **Figure 1's microbiome feature count was corrected (fixed 2026-08-11):
   463 genera → 147.** 463 came from the superseded Greengenes annotation and
   cannot arise from the SILVA release this analysis uses, which has 429 distinct
   genus-level lineages in total (351 distinct genus labels) — filtering only
   removes taxa, so no stage of the pipeline can produce 463. 147 is what
   survives the ANCOM-BC2 prevalence filter and enters the models, which is what
   the two sibling boxes report and what the manuscript Methods already say
   (*"147 genera passed ANCOM-BC2 prevalence filtering"*). `revision_notes.md`
   had already flagged 463 as unreproducible; Figure 1 was the last place it
   survived. `participant_flow_counts()` now verifies all ten Figure 1 counts —
   participants **and** feature blocks — against the data, and `04_` stops on any
   mismatch.
4. **Figure 3's sign conventions need one deliberate decision.** The elastic-net
   direction here (`estimate > 0` → protective) matches the manuscript text; the
   re-run had it inverted. But this tree also flips the XGBoost SHAP sign in
   `Supplementary_Fig1`, where the re-run does not. See `manuscript/bug_fix.md`.
5. **`Supplementary_Fig5_primary_modeling_workflow.pdf` and
   `Supplementary_Fig6_matched_cohort_workflow.pdf`** exist in the manuscript
   folder but are produced by no code here, so `sync_submission_assets.R` will
   delete them.
6. **`data/processed_data/df_status_*.rds` are the re-run's frozen frames**, not
   the ones behind `single_omics/`. They differ only in `fr_chs4` (128/765 rows),
   which is excluded from modeling — but it means refitting via
   `code/single_omics/run_omics_pred.R` would not reproduce `single_omics/` exactly. The
   published results remain fully reproducible from the saved outputs.
